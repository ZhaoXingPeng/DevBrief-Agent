# 实验记录与 PR 证据规范

DevBrief 的实验记录不是宣传材料，而是帮助 Reviewer、未来维护者和作者自己判断“该结论是否值得相信”的工程证据。记录真实结论，包括失败、波动和未覆盖范围。

## 1. 证据等级

| 等级 | 名称 | 可以证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| E0 | 设计假设 | 问题和预期方案值得尝试 | 实现可行或质量达标 |
| E1 | 单元/契约 | 特定规则、Schema、状态转移在固定输入下正确 | 真实 provider 或端到端体验 |
| E2 | fake 集成 | 用例与 Adapter 边界可串联、错误路径可控 | 第三方服务实际表现 |
| E3 | sandbox 集成 | 特定测试账号/仓库的真实协议与权限可用 | 生产数据、规模和可靠性 |
| E4 | 真实受控实验 | 明确环境与样本下的真实链路结果 | 超出样本、模型版本或时间窗口的普遍结论 |

PR 必须标注证据等级。禁止把 E1/E2 描述为“端到端通过”，禁止把一次 E4 成功描述为“已生产可用”。

## 2. 何时必须记录实验

- 性能、延迟、成本、准确率、召回率、排序质量或模型行为；
- ASR/LLM/检索/provider 的真实或 sandbox 集成；
- 外部写、幂等、恢复、超时、限流、权限或安全修复；
- 与原设计不同的实现选择或被否决的方案；
- 修复缺陷时的最小复现和回归证据。

纯文案、无行为的格式调整不需要凑实验记录，应写“不涉及”。

## 3. PR 评论格式

每个有意义的实验、真实环境预检、失败或回退决定及时追加评论：

```text
阶段：<D0 设计 / D1 契约 / D2 fake / D3 sandbox / D4 real>
假设：<需要验证的命题>
环境：<commit、依赖版本、provider/模型版本、样本版本；不含秘密>
输入：<样本规模、选择规则、脱敏描述或受控路径>
命令：<可复制的命令>
结果：<原始计数、时延、错误、断言或 artifact 摘要>
结论：<接受、拒绝、阻塞或下一步>
限制：<不能外推的范围、未覆盖路径和风险>
```

算法、性能、稳定性或 Agent 质量使用 STAR 补充：

```text
Situation（情境）：现象、规模与影响
Task（任务）：目标和验收阈值
Action（行动）：数据、算法、提示词、策略或代码变化
Result（结果）：基线、结果、统计口径、测试与剩余风险
```

## 4. 特定场景的最低记录

### Agent 质量评测

- 标注集版本、样本数量、采样规则和排除条件；
- 模型/提示词/检索索引/工具版本；
- 指标定义：行动项 Precision/Recall/F1、字段准确率、证据覆盖、重复 Issue Top-k；
- 失败样本类别和是否修正评测集；
- 不在日志中保存原始私密音频或完整转写。

### 外部写工具

- 目标是 fake、sandbox 还是 real；
- 审批批准、拒绝、过期、篡改 plan、超时未知结果、重放与重复请求的断言；
- 外部对象 ID/URL 的脱敏引用或受控位置；
- 回退/补偿计划。

### 性能与成本

- 输入规模、机器/网络、运行次数、热身、统计口径；
- 基线和候选实现使用同一输入；
- 至少报告均值与分位数或分布，不只给单次最好结果；
- 模型成本按请求、token、音频时长或工具调用明确计量口径。

## 5. 留存与脱敏

原始音频、完整转写、真实 token、全量 trace 和外部私有内容只保留在受控本地/测试环境，不提交 Git。仓库中只保留可公开的固定 fixture、合成样本、统计摘要、命令、版本哈希和脱敏 artifact 索引。

## 6. 参考实践

VoiceLife PR #359 的价值不在评论数量，而在于它分阶段记录干净构建、真实板卡输入、严格断言、失败轮次、恢复过程和不可外推范围。DevBrief 采用同一原则，但把硬件证据替换为会话、模型、工具与审批证据。
