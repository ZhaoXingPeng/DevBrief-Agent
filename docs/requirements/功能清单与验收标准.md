# DevBrief Agent 功能清单与验收标准

**版本：** 0.2-draft

**原则：** 本文只定义交付行为、流程和验收；产品动机、边界和质量约束以《需求规格说明》为准。本文所有功能均为待实现要求，不是现有功能声明。

## MVP 功能地图

```text
F0 Harness 生命周期与预算
  -> F1 版本化输入 Fixture
  -> F2 决策候选与澄清
  -> F3 证据检索与上下文控制
  -> F4 任务计划与去重
  -> F5 策略与人工审批
  -> F6 受控外部写与恢复
  -> F7 Trace、回放与 Eval
```

## F0：单 Agent Harness 生命周期与执行预算

**目标：** 用显式状态图运行一个研发决策会话，并在循环、超时、取消和失败时安全停止或恢复。

**MVP 行为：** 会话绑定状态、`max_steps`、`max_tool_calls`、`deadline_at`、`max_model_tokens` 和 `max_cost`；每次状态改变和工具结果形成 checkpoint/trace。MVP 只支持单 Agent。

**验收：**

```text
Given 一个新会话和确定的 ExecutionBudget
When Harness 依次处理输入、分析、计划、审批和执行
Then 每次状态迁移符合契约，记录 trace_id、causation_id 和预算消耗

Given 已达到 max_steps、deadline 或成本预算的会话
When Harness 尝试继续处理
Then 停止后续模型/工具调用，记录结构化停止码与最后安全 checkpoint

Given 被取消或发生可恢复 provider 错误的会话
When 用户请求恢复
Then 只能从最后安全 checkpoint 继续；不得重新执行已有 receipt 的外部写
```

**非目标：** 不实现多 Agent、分布式调度或代码执行沙箱。

## F1：版本化转写输入

**目标：** 以确定性、可复现的转写输入建立 Agent 基线；音频是后续可替换输入 Adapter。

**MVP 行为：** 支持导入带时间戳、样本版本和脱敏标记的固定转写 fixture；为会话生成稳定 ID 并按时间顺序保存 `transcript_segment`。

**验收：**

```text
Given 一个有效、版本化且脱敏的转写 fixture
When 用户创建会话
Then 系统生成稳定 session_id，记录 fixture_version，并按时间顺序保存 transcript_segment

Given 一个缺少版本、时间戳或必填字段的 fixture
When 用户导入该输入
Then 系统返回结构化 validation_error，不创建半完成计划或 checkpoint
```

**非目标：** MVP 不要求音频上传、浏览器系统音频、实时字幕、TTS 或真实 ASR。

## F2：决策候选与澄清

**目标：** 从转写中输出结构化决策、行动项、风险或待澄清项。

**验收：**

```text
Given 包含“P0、张三、本周五前修复”的转写段
When 系统分析会话
Then 生成带 transcript 证据的 DecisionCandidate，字段使用受控枚举

Given 转写未说明负责人或期限
When 系统分析会话
Then 候选字段标记为 unknown 或 ambiguous，并生成澄清问题；不得猜测人员或日期

Given 模型返回不符合 Schema 的结果
When 系统校验候选
Then 拒绝该结果并记录 validation_error，不进入任务计划
```

## F3：仓库证据检索与上下文控制

**目标：** 将候选决策与代码、ADR 和历史 Issue 关联，并把不可信检索结果限制在数据边界内。

**验收：**

```text
Given 一个提及认证刷新故障的候选
When 系统调用 GitHub 只读工具
Then 返回可追溯的文件/ADR/Issue 证据、工具调用时间、上下文预算消耗和检索失败信息

Given 检索到含有恶意或指令性文本的 Issue
When Context Builder 构建模型输入
Then 该文本有来源标记且只作为证据内容，不能改变工具 allowlist、预算、审批状态或系统策略

Given 证据超过当前上下文预算
When 系统构建上下文
Then 记录裁剪理由和保留引用；不得静默截断后进入外部写计划
```

**非目标：** 不声称代码搜索能够理解全部仓库；低相关结果必须呈现不确定性。

## F4：重复检测与任务草稿

**目标：** 生成可审阅的 GitHub Issue 草稿，并提示可能重复项。

**验收：**

```text
Given 有证据的 action_item 和检索结果
When 系统生成计划
Then 草稿包含标题、背景、验收条件、风险、证据、相似 Issue 及其理由，并生成稳定 plan_hash

Given 相似度不足或证据不足
When 系统生成计划
Then 不将任何已有 Issue 标为“确定重复”，而是标记待人工判断

Given 用户编辑草稿内容
When 计划内容发生变化
Then plan_hash 改变，旧 approval 失效，并要求重新策略检查和批准
```

## F5：策略检查与人工审批

**目标：** 让 Agent 建议与外部副作用之间存在确定性安全边界。

**验收：**

```text
Given 一个 external_write 计划
When 未通过 policy_check、缺少有效 approval 或超出工具 scope
Then 工具不可调用，并返回 policy_denied、approval_required 或 tool_not_allowed

Given 用户批准了某个 plan_hash 和精确 action scope
When 计划参数、目标仓库或权限范围被修改
Then 原 approval 自动失效

Given approval 已过期、被拒绝或已消费
When 尝试执行同一写操作
Then 系统拒绝执行并保留审计记录
```

## F6：GitHub Issue 受控创建与恢复

**目标：** 在批准后仅创建一次 GitHub Issue，并保存可查询回执。

**验收：**

```text
Given 有效审批、同一 idempotency_key 和合法参数
When 系统执行 create_issue
Then 保存外部 Issue ID/URL、provider 请求信息、ToolReceipt 和新的 checkpoint

Given provider 超时且结果未知
When 恢复会话
Then 系统先查询幂等键或目标 Issue；在无法确认前状态为 unknown_outcome，不盲目重试

Given 同一个经批准计划被重复提交或从 checkpoint 重放
When 执行请求重放
Then 返回原始回执，不创建第二个 Issue
```

**非目标：** MVP 不创建分支、不修改代码、不分配人员、不自动关闭重复 Issue。

## F7：Trace、回放、评测与导出

**目标：** 让 Reviewer 能复原 Agent 的建议、依据、预算、批准与执行过程，并以固定样本评测质量。

**验收：**

```text
Given 一次已完成、取消或失败的会话
When 用户查看 trace
Then 可看到状态迁移、预算变化、证据引用、工具调用摘要、policy 结果、approval、checkpoint 和 receipt；不展示秘密或全量私密内容

Given 一个版本化的标注样本集
When 运行 Eval 与 Replayer
Then 报告样本版本、模型/提示词版本、行动项指标、字段指标、证据覆盖、工具选择、停止原因和失败类别

Given 一个历史 trace
When 在 fake 环境回放
Then 比较状态、plan_hash、工具决策和 receipt 引用，并报告不可重放或发生漂移的位置
```

## 延后功能

| 功能 | 延后原因 |
| --- | --- |
| 音频上传、流式 ASR、浏览器/系统音频采集 | 先验证 Harness、任务闭环和安全边界，再扩展输入体验 |
| Linear Adapter | 先以 GitHub 单一写 Adapter 固化审批/回执契约 |
| 多 Agent 协作 | 单 Agent 基线和对照 Eval 证明需要后才引入 |
| 独立向量数据库 | 先以可解释检索建立基线，再判断是否存在召回瓶颈 |
| 自动代码修改、PR 合并和通用沙箱 | 风险、权限和隔离边界远超当前产品目标 |
| 跨组织持久记忆 | 涉及权限、数据留存和租户隔离，需单独 Design/ADR |
| SFT、RL、Agentic RL | 作为算法岗位独立实验，不阻塞 Agent Harness 主线 |
