# DevBrief Agent 需求规格说明

**版本：** 0.2-draft

**状态：** Harness-first 架构已确认，待实现验证
**目标读者：** 产品负责人、研发负责人、架构/安全 Reviewer、实现者

## 1. 背景与问题

研发会议中的关键信息往往以口语出现：缺陷优先级、负责人、期限、风险、技术决定和验收口径。现有会议助手能提供转写、摘要和待办，但通常无法结合仓库模块、ADR、历史 Issue 和权限边界判断“是否值得创建、应如何创建、是否会重复、谁有权执行”。

更重要的是，研发 Agent 的价值不在一次模型输出，而在不确定输入、检索证据、工具调用、外部副作用、失败恢复和质量回归组成的闭环。若项目先投入实时音频或多 Agent 编排，容易掩盖这些更基础的工程问题。

## 2. 目标用户与场景

| 用户 | 场景 | 需要的结果 |
| --- | --- | --- |
| Tech Lead / 项目负责人 | Bug Triage、Sprint Review、设计评审 | 将会议决定转为带负责人、优先级、期限、验收条件和证据的任务草稿 |
| 开发者 | 参与跨团队讨论或故障复盘 | 快速定位与决定有关的代码、ADR、历史 Issue 和待澄清项 |
| Reviewer / 工程经理 | 审核自动化建议或外部写入 | 看见决策来源、检索依据、审批链、执行回执、预算和失败原因 |

首个垂直场景是**研发 Bug Triage**，而不是销售、客服、通用办公会议或自动编码。

## 3. 产品目标

1. 以版本化转写或后续音频输入，可靠提出决策、行动项、风险和待澄清项。
2. 让每个任务草稿附带可定位的转写和仓库证据，避免“黑盒摘要”。
3. 用受限的单 Agent Runtime 编排检索、计划、审批和执行，能够停止、取消、恢复和回放。
4. 用策略校验、人工审批、幂等写入和回执将 Agent 建议与外部副作用隔离。
5. 以版本化评测集、trace 和回归报告证明质量，不依赖主观 Demo。
6. 让本地无凭据 fake Demo 与真实集成共享领域契约，避免将 mock 成功写成真实能力。

## 4. 非目标

- 不替代 Zoom、飞书、腾讯会议、通义听悟等通用会议系统。
- 不自建电话呼叫、TTS 呼叫中心或通用语音 Agent 基础设施。
- 不在 MVP 自动创建分支、修改代码、运行危险命令或合并 PR。
- 不将任何模型输出、检索内容或用户口语直接视为有权执行的指令。
- 不在没有对照 Eval 的情况下默认采用多 Agent。
- 不承诺医疗、法律、财务或人事决策准确性。

## 5. 范围与交付顺序

### Phase 1：Harness 基线

- 版本化、脱敏或合成的带时间戳转写 fixture；
- 类型化会话事件、单 Agent 状态图、执行预算、取消和 checkpoint 语义；
- canonical Tool Registry、读/草稿/外部写工具分级；
- fake 默认路径、结构化 trace 和回放要求。

### Phase 2：研发决策工作流

- 决策候选、字段校验和待澄清呈现；
- GitHub 仓库只读检索：代码、ADR、开放 Issue、相似 Issue；
- 上下文预算、证据引用和提示注入隔离；
- 本地 Issue 草稿、重复检测和任务计划。

### Phase 3：受控外部副作用

- 策略检查、人工审批、计划哈希和幂等键；
- GitHub Issue 受控创建、回执、未知结果查询优先和恢复；
- SQLite 本地 Demo 与 PostgreSQL 服务端存储的同一 Repository Port。

### Phase 4：质量与交付

- 标注集、Eval runner、失败分类、回归报告和基线比较；
- 可观测 trace、指标、回放界面/命令、CI 和容器化；
- 真实集成仅在 sandbox/real 证据齐全时标记。

### Phase 5 及以后

- 音频上传、ASR、实时体验和时延实验；
- Linear Adapter、多仓库和受控团队术语；
- 多 Agent 对照实验；
- 编码 Agent 的仅建议交接。代码执行、自动代码修改和 PR 合并仍需独立 ADR。

## 6. 需求

### R1：证据优先的任务建议

系统必须把任务建议与至少一个转写段、音频时间段（接入后）或人为补充关联；当使用仓库结论时，必须列出文件、ADR 或 Issue 证据。无证据的内容只能作为待澄清，不得作为自动建单依据。

### R2：不确定性显式化

负责人、期限、优先级、影响范围或验收条件无法确认时，系统必须标记 `unknown` 或 `ambiguous`，并生成澄清问题；不得用模型常识补全。

### R3：可控单 Agent Runtime

会话必须由显式状态图和确定性命令驱动，而非由 UI 文本或模型自然语言改变状态。启动时绑定 `max_steps`、`max_tool_calls`、`deadline_at`、`max_model_tokens` 和 `max_cost` 等执行预算；预算耗尽、取消、Policy 拒绝或 Schema 失败必须停止后续执行并保留 trace。

### R4：上下文与工具边界

系统必须区分系统规则、用户输入、仓库证据和工具结果，并对每个区段保留来源与预算。工具只能从 canonical registry 发现和调用，且按 `read`、`draft_write`、`external_write` 分级；MCP 只能作为受该注册表约束的 Adapter 协议，不能绕过策略。

### R5：受控工具执行

创建外部 Issue 前必须完成确定性参数校验、策略检查、未过期人工批准、计划哈希校验、幂等键和回执保存。Agent 只能提出计划，不能直接拥有外部写权限。

### R6：失败安全、检查点与恢复

任何网络超时、限流、权限失败、预算耗尽或未知写入结果都必须保留最后安全 checkpoint 和错误分类。未知外部写结果先查询是否已写入，禁止盲目重试造成重复任务；恢复不得越过失效审批或重复已有回执的外部写。

### R7：可评测性、可观测性与回放

系统必须保存可审计 trace，并能在 fake 环境按事件顺序回放。评测必须固定样本/标注版本、模型/提示词版本、指标口径和失败类别；至少覆盖候选字段、证据覆盖、工具选择、Policy 拒绝、恢复、回放、时延和成本。

### R8：隐私与最小暴露

原始音频、转写、私有仓库内容和 token 不得写入仓库或公开日志。系统只存储完成产品目标所需的最小数据；trace、checkpoint 和 Eval artifact 必须脱敏并支持会话数据删除策略。

### R9：本地可复现性

每个 Phase 都必须有不依赖真实凭据、在线模型或真实音频的确定性 fake 路径。真实 Provider、GitHub 和 ASR 实验需要单独标记环境、输入范围、结果和不可外推边界。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可解释性 | 每个候选、计划和写入回执可追溯到事件、证据、预算和策略决定 |
| 安全 | 最小 OAuth scope；prompt injection 防护；写工具批准、幂等和审计 |
| 可靠性 | 状态可恢复；外部写幂等；超时分类；失败关闭；取消可审计 |
| 性能与成本 | MVP 先保证正确性；所有模型/工具调用可记录时延和成本；实时目标在 ASR 阶段由实验确定 |
| 可维护性 | 契约单一事实源；端口/适配器分层；测试可在无外网环境运行 |
| 可移植性 | Provider、Issue Tracker、存储和编排实现通过 Port 替换，不向领域层泄露 SDK 类型 |

## 8. 成功标准

Phase 1-4 的完成不以“看起来像 Agent”为准，而以以下证据判断：

- 固定标注集上的行动项 Precision、Recall、F1 与字段准确率；
- 可执行建议的证据覆盖率达到 100%；
- 相似 Issue Top-1/Top-3 命中率可报告；
- 未确认外部写入次数为 0；
- 超时/重放下重复建单次数为 0；
- 预算耗尽、取消、拒绝、审批过期和恢复都可从 trace 复原；
- Replayer 在 fake 环境可复现状态、计划哈希和工具决策；
- Reviewer 能从 trace 还原一次建议、审批、执行和回执。

具体数值阈值在积累基准样本后写入对应 Feature Issue，不能在没有数据时伪造目标达成。

## 9. 风险与待验证假设

| 风险/假设 | 缓解与验证 |
| --- | --- |
| ASR 错误导致错误任务 | 先用转写 fixture 建立基线；接入后保留音频证据、低置信度澄清和错词样本集 |
| LLM 从口语中补造事实 | Schema、未知状态、策略约束和人工审批 |
| Agent 循环或成本失控 | 执行预算、deadline、检查点、停止码和 Eval 中的循环 fixture |
| 仓库检索被提示注入污染 | 将检索内容隔离为数据；工具权限、状态和审批不由文本决定 |
| 相似 Issue 误判 | 展示候选与理由，不自动关闭/合并 Issue |
| 外部写超时结果未知 | 幂等键、查询优先、`unknown_outcome` 状态和回放测试 |
| 多 Agent 增加复杂度却没有收益 | 单 Agent 基线与对照 Eval 是准入条件 |
| 真实语音数据隐私 | 合成 fixture、最小留存、脱敏日志和受控真实实验 |
